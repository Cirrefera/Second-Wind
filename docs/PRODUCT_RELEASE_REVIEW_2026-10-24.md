## AWS-0568: DynamoDB request planner

- **Service and contract:** Reviewed both planners, all eight feature modules, the selection schema and README. The table uses agent/session string keys, on-demand billing and AWS-managed KMS. The status GSI projects keys only. TTL and recovery use their own operations after activation; streams request old/new images. AWS documentation confirms the operation boundaries: [CreateTable](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_CreateTable.html), [UpdateTimeToLive](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_UpdateTimeToLive.html), and [UpdateContinuousBackups](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_UpdateContinuousBackups.html). The product generates requests and expected states; it does not execute AWS calls or match responses.
- **Product and scope:** The paid deliverable is a 13-file package with independently selectable features. All optional features explicitly require the table. The $5 maximum and $2/$1/$0.50/$1/$0.50 allocation match the approved schedule. Existing scope code sums selected components and binds the configuration and file identities. It does not charge for sandbox use. README pricing text was corrected before freezing the release.
- **Languages and sandbox:** JavaScript and Python planner source are included per selected component; configuration explicitly chooses the implementation. Code Mode executes JavaScript only. README now states that limitation and does not represent the JavaScript trial as Python execution. The existing production workflow [40120724077](https://github.com/Cirrefera/Second-Wind/actions/runs/40120724077) verified all 16 actual JavaScript feature packages in Dynamic Workers, including omitted-module and secret isolation. Planner and feature bytes are unchanged by this review; only README bytes changed in the delivered package.
- **Validation:** Existing `validation.json` records both language variants, 32 plans, 160 operation inputs and 64 partial response shapes against botocore 1.43.114. Its pinned source hashes match the current files. This evidence covers offline planning, not an AWS deployment. No new tests were added or run locally for this review.
- **Origin and license mapping:** Reviewed the original planner/module implementations, checked-in Apache-2.0 license and provenance record. No DynamoDB Tools source or SDK implementation is packaged. The mapping covers the 13 delivered files; AWS documentation supplies interface references. This is a source-level mapping assessment, not a universal originality guarantee.
- **Routing:** The manifest advertises request planning for a new table and the two implemented languages. It excludes existing-table migration, global tables, IAM creation, customer-managed KMS, deployment and immediate TTL deletion. These exclusions match the deliverable.

## SW-PT-0006: Python idempotency guidance

- **Service and contract:** Reviewed the complete Markdown, `example.py`, requirements and pinned upstream inspection. Required fields are checked before persistence/payment. The wrapper binds a stable order ID, validates customer/amount/currency and hands the same business key to a buyer-supplied payment function. [Official Powertools documentation](https://docs.aws.amazon.com/powertools/python/latest/utilities/idempotency/) supports the configuration fields, replay, concurrent-invocation rejection and table permissions. The guide explicitly explains the non-atomic external payment boundary and expiration window.
- **Product and languages:** This is $1 whole-product guidance, containing a complete Python example. It is not a hosted payment processor or a component sandbox product. Python is the only advertised adapter. Historical v1 TypeScript/Java/.NET claims are not carried into its routing metadata.
- **Validation:** The existing seven-case record covers actual Powertools 3.36.0 with fake DynamoDB I/O. All recorded source hashes match. This review changes only draft-status wording in the delivered Markdown; the example, dependencies and validation implementation are unchanged. No AWS operation, payment or new local test run was performed.
- **Origin and license mapping:** The independently authored wiring and guidance carry the checked-in Apache-2.0 mapping. The separately installed Powertools dependency is MIT-0, as recorded by the pinned upstream license text and revision. No upstream implementation is vendored into the guidance. The historical source record and v1 bytes remain preserved.
- **Routing:** The metadata targets duplicate-side-effect guidance for Python Lambda, excludes payment processing, exactly-once external effects, other languages, SQS batches and deployment, and requests explicit language selection. Those boundaries match the actual content.
